# 소프트웨어 요구사항 명세서(SRS) v0.1

| 항목 | 내용 |
|---|---|
| 대상 시스템 | 교내 분실물 관리 서비스 |
| 버전 | v0.1 |
| 작성 근거 | `고객 요구사항.md`의 고객 인터뷰, 개발 범위 및 공통 제약 |
| 목적 | 학생의 행정실 방문 전 분실물 보관 여부·위치 확인을 지원하고, 행정 담당자의 분실물 등록 및 인도 상태 관리를 지원한다. |

## 0. 확정 사항

| ID | 확정 내용 | 적용 범위 |
|---|---|---|
| DEC_00 | 습득 학생은 습득한 물품을 앱으로 직접 등록한다. | 습득물 등록 |
| DEC_01 | 행정 담당자는 분실물 센터로 접수된 습득 물품을 관리하기 위해 물품 정보를 등록한다. | 분실물 관리 |

## 1. 기능 요구사항

| ID | 기능 요구사항 | 사용자/주체 | 우선순위 | 근거 | 비고 |
|---|---|---|---|---|---|
| FR_00 | 시스템은 분실물 정보를 조회할 수 있는 기능을 제공해야 한다. | 분실 학생 | 높음 | NEEDS_1, SC1 | 구체적인 검색 조건은 미정이다. |
| FR_01 | 시스템은 조회 결과에서 분실물의 보관 여부와 보관 위치를 확인할 수 있도록 해야 한다. | 분실 학생 | 높음 | NEEDS_1, S1 | 공개 가능한 세부 항목은 Pol_00을 따른다. |
| FR_02 | 시스템은 행정 담당자가 분실물 센터로 접수된 습득 물품의 정보를 등록할 수 있도록 해야 한다. | 행정 담당자 | 높음 | NEEDS_2, SC2, DEC_01 | 필수 입력 항목은 추후 확정한다. |
| FR_03 | 시스템은 각 분실물에 보관 상태를 기록해야 한다. | 행정 담당자 | 높음 | NEEDS_3, SC3 | 상태 값은 최소한 `보관 중`, `인도 완료`를 구분한다. |
| FR_04 | 시스템은 조회 시 보관 중인 물품과 인도 완료된 물품을 구분하여 표시해야 한다. | 분실 학생, 행정 담당자 | 높음 | NEEDS_3, SC3 | 인도 완료 물품의 노출 방식은 공개 정책에 따라 확정한다. |
| FR_05 | 시스템은 분실 학생이 보관 담당 부서와 문의 방법을 확인할 수 있도록 안내해야 한다. | 분실 학생 | 높음 | NEEDS_4, SC6 | 구체적인 부서명·연락/문의 수단은 운영 정책으로 확정한다. |
| FR_06 | 시스템은 가상 데이터를 이용해 분실물 조회·등록·상태 관리 기능을 제공해야 한다. | 시스템 | 높음 | C_1 | 실제 개인정보 및 학교 인증 연동은 포함하지 않는다. |
| FR_07 | 시스템은 습득 학생이 습득한 물품 정보를 앱으로 직접 등록할 수 있도록 해야 한다. | 습득 학생 | 높음 | DEC_00 | 등록 항목, 등록 후 처리 절차 및 공개 시점은 추후 확정한다. |

## 2. 비기능 요구사항(품질 요구사항)

| ID | 품질 특성 | 비기능 요구사항 | 검증 기준/결정 사항 | 근거 |
|---|---|---|---|---|
| NFR_00 | 사용성 | 분실 학생은 행정실 방문 전에 보관 여부, 보관 위치 및 문의 방법을 한 화면 흐름에서 이해할 수 있어야 한다. | 사용자 검토를 통해 해당 정보를 별도 문의 없이 찾을 수 있는지 확인한다. 세부 화면 구성은 미정이다. | 서비스 목표, S1, NEEDS_1, NEEDS_4 |
| NFR_01 | 업무 효율성 | 분실물 등록 과정은 습득 학생과 행정 담당자가 각자의 등록 목적에 필요한 정보만 입력하도록 구성해야 한다. | 입력 항목, 현재 소요 시간, 목표 소요 시간 및 측정 방식은 추후 정의한다. | 서비스 목표, S2, NEEDS_7, DEC_00, DEC_01 |
| NFR_02 | 정확성 | 조회 결과의 보관 위치와 보관 상태는 행정 담당자가 등록·관리한 정보와 일치해야 한다. | 등록 정보와 조회 화면의 표기 일치 여부를 테스트한다. 상태 변경 및 정정 절차는 미정이다. | NEEDS_1, NEEDS_3 |
| NFR_03 | 개인정보 보호 | 조회 화면은 개인 휴대전화 번호를 공개하지 않아야 한다. | 공개 화면에 개인 휴대전화 번호가 포함되지 않는지 확인한다. | S4, S5, SC8, NEEDS_6 |
| NFR_04 | 정보 최소 공개 | 조회 목적에 필요한 정보만 공개하도록 공개 항목을 제한해야 한다. | 공개 항목 목록을 정보보호 담당자가 검토·확정한다. 현재 휴대전화 번호 외 항목은 미정이다. | S4, NEEDS_6 |
| NFR_05 | 성능 | 조회 및 등록 기능의 응답 시간 목표를 정의하고 이를 충족해야 한다. | 목표 응답 시간, 동시 사용자 수 및 측정 환경은 미정이다. | 고객 요구사항에 정량 목표 미정으로 명시 |
| NFR_06 | 가용성 | 서비스 운영 시간과 허용 가능한 장애·복구 기준을 정의해야 한다. | 운영 시간, 가용성 목표 및 백업·복구 기준은 미정이다. | 운영 책임자 이해관계자, 운영 정책 미정 |
| NFR_07 | 유지보수성 | 등록 정보의 수정 권한과 정정 이력 관리 방식을 정의해야 한다. | 권한 주체, 수정 가능 범위 및 이력 보관 여부는 미정이다. | SC3의 처리 권한·정정 방법 미정 |

## 3. 정책

| ID | 정책 | 적용 대상 | 근거 | 상태 |
|---|---|---|---|---|
| Pol_00 | 조회 화면에서 공개할 정보는 조회 목적에 필요한 최소 범위로 제한한다. 개인 휴대전화 번호는 공개하지 않는다. | 조회 화면, 등록 데이터 | S4, SC8, NEEDS_6 | 휴대전화 번호 비공개 확정 / 그 외 공개 항목 미정 |
| Pol_01 | 개발 및 검증에는 가상 데이터만 사용하며 실제 개인정보는 저장·처리하지 않는다. | 전체 시스템, 테스트 데이터 | C_1 | 확정 |
| Pol_02 | 학교 인증 또는 학교 계정 연동은 이번 버전에 포함하지 않는다. | 인증·연동 기능 | C_1 | 확정 |
| Pol_03 | 사진 업로드를 통한 유사 분실물 검색 및 사진 자동 매칭은 이번 개발 범위에서 제외한다. | 이미지 검색·매칭 기능 | SC5 | 확정 |
| Pol_04 | 사진 매칭 결과에 기반한 분실 학생 자동 알림은 이번 개발 범위에서 제외한다. | 알림 기능 | SC7 | 확정 |
| Pol_05 | 습득물이 맡겨질 장소 안내의 프로그램 포함 여부는 운영 주체가 확인한 뒤 결정한다. | 습득물 안내 기능 | SC4, NEEDS_5 | 미정 |
| Pol_06 | 분실물 상태는 최소 `보관 중`과 `인도 완료`로 구분한다. 인도 처리 권한, 상태 변경 조건 및 정정 방법은 운영 정책으로 확정한다. | 분실물 상태 관리 | SC3, NEEDS_3 | 상태 구분 확정 / 세부 처리 미정 |
| Pol_07 | 보관 담당 부서와 문의 방법의 실제 표기 내용은 운영 주체가 확정한다. | 문의 안내 | SC6, NEEDS_4 | 미정 |
| Pol_08 | 서비스 운영 책임자, 역할별 권한 및 공개 항목의 최종 승인 절차는 학교 운영 주체와 정보보호 담당자가 결정한다. | 운영·권한·공개 정책 | 이해관계자 목록, S4 | 미정 |
| Pol_09 | 습득 학생의 앱 직접 등록과 행정 담당자의 분실물 센터 접수 물품 등록은 별도 등록 경로로 제공한다. | 등록 기능 | DEC_00, DEC_01 | 확정 |

## 4. 범위 제외 및 추후 확인 항목

| 구분 | 항목 | 처리 방침 |
|---|---|---|
| 범위 제외 | 사진 업로드, 유사 분실물 검색, 사진 자동 매칭 | 후속 개선 후보로 관리한다. |
| 범위 제외 | 사진 매칭 기반 자동 알림 | 이번 버전에서는 문의 방법 안내로 대체한다. |
| 범위 제외 | 개인 휴대전화 번호 공개 | 개인정보 보호 정책에 따라 제공하지 않는다. |
| 범위 제외 | 실제 개인정보 및 학교 인증 연동 | 가상 데이터 기반으로 구현한다. |
| 추후 확인 | 검색 조건, 등록 필수 항목, 공개 항목 | 운영 주체 및 정보보호 담당자와 확정한다. |
| 추후 확인 | 인도 처리 권한, 상태 정정 절차, 수정 이력 | 운영 정책으로 확정한다. |
| 추후 확인 | 성능·가용성 목표와 측정 방법 | 운영 환경과 예상 사용량을 기준으로 수치화한다. |
